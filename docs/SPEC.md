# フィニッシャージャーナル Web版 仕様書

- 版: v0.2（タスク台帳・Notion連携を追加）
- 作成日: 2026-09-27
- 対象: 紙の「フィニッシャージャーナル」（90日ジャーナル）をWebアプリ化する
- ステータス: **おおむね了承済み**（2026-09-27 に方向性OK。残る確認事項は末尾「11. 確認事項」）

---

## 1. 目的と背景

紙で長らく使ってきた90日ジャーナルを、スマホ・PCのどちらからでも書けるWebアプリにする。
紙の良さ（1日1ページ、3ヶ月目標が常に目に入る）を保ちながら、次の点を改善する。

- 3ヶ月の目標を**毎日のページに必ず表示**し、忘れないようにする
- 目標ごとの**達成度合い（進捗）を自動で可視化**する
- スケジュール欄は **Googleカレンダーそのもの**を読み書きし、二重管理をなくす
- 毎日の「やるべきこと」を **タームを通して積み上げ**、92日後に「何ができて、何ができなかったか」を一覧で見られるようにする
- やるべきことは **Notion と連携**し、Notion 側からも見て・チェックできるようにする
- 3ヶ月ごとに新しいタームを作り、過去のタームも振り返れるようにする

## 2. 用語

| 用語 | 意味 |
|---|---|
| ターム | 3ヶ月（約90日）の1単位。目標はターム単位で立てる。最初は 2026-10-01〜2026-12-31 |
| プロジェクト目標 | ターム中に「完了」させる成果物型の目標。マイルストーン（小タスク）の完了率で進捗を出す |
| 習慣目標 | ターム中に「続ける」行動型の目標。毎日のチェックの積み上げで進捗を出す（※下記 確認事項 1） |
| デイリーページ | 1日1ページのジャーナル。スケジュール／やるべきこと3つ／集中すべきこと／習慣チェック／良かったこと |
| Day N | タームの何日目か。10/1 が Day 1、12/31 が Day 92 |
| タスク台帳 | タームの全日のやるべきことを1つの表にした画面。できた／できなかったをチェックし、ターム終了後に総括を表示する |

## 3. スコープ

### 3.1 フェーズ1（MVP：今回作るもの）

1. Googleアカウントでログイン（利用者は本人のみ。許可メールアドレスのみ通す）
2. タームの作成・一覧・切り替え
3. ターム目標の設定（プロジェクト目標／習慣目標）と進捗表示
4. デイリーページ（1日1ページ、自動保存）
5. デイリーページ上での Googleカレンダー連携（当日の予定の表示・追加・編集・削除）
6. タームのダッシュボード（残り日数、各目標の進捗、習慣の達成カレンダー）
7. タスク台帳（ターム内の全タスクの一覧、できた／できなかったのチェック、ターム終了時の総括）
8. Notion連携（やるべきことを Notion データベースへ同期。完了チェックは双方向）

### 3.2 フェーズ2（あとで）

- 週次レビュー（紙版の週末ふりかえり相当）
- タームの最終ふりかえりページ（達成した／しなかった／次に活かす）
- 未完了タスクの翌日への自動繰り越し（台帳の「できなかった」から翌日へ送る操作はフェーズ1に含める）
- 「良かったこと」の一覧・検索
- 通知（朝のリマインド：メール or カレンダー通知）
- 紙ジャーナルの過去分の取り込み（手入力用の一括入力画面）

### 3.3 やらないこと

- 複数人での共有・コメント機能
- ネイティブアプリ（PWA としてホーム画面追加で代替）
- Googleカレンダー以外のカレンダー連携
- Notion 以外のタスクツール連携（Todoist 等）

## 4. ターム（90日）の扱い

- タームは **開始日・終了日・タイトル** を持つ。既定は暦の四半期（10/1〜12/31、1/1〜3/31、…）。
- 「90日」は呼称であり、実際の日数は暦どおり（最初のタームは 92日）。Day 表記は実日数で数える。
- 同時に有効なタームは1つ。終了日を過ぎたら「次のタームを作る」ボタンをダッシュボードに出す。
  次タームを作るとき、前タームの未達目標を引き継ぐか選べる。
- 過去タームは読み取り専用で閲覧できる（目標・進捗・各日のページ）。

## 5. 目標と進捗

### 5.1 プロジェクト目標

| 項目 | 内容 |
|---|---|
| タイトル | 例「新茶の卸先を3件増やす」 |
| なぜやるか（任意） | 動機の一言。デイリーページのツールチップに出す |
| 期限 | 既定はターム終了日。前倒しも可 |
| マイルストーン | 小タスクのリスト（3〜10個程度）。チェックで完了 |
| 進捗 | 完了マイルストーン数 ÷ 全マイルストーン数（%）。マイルストーン0件のときは手動の％スライダー |
| 状態 | 進行中／達成／未達／中止 |

- 目標数の目安は 3〜5個。上限は設けないが、6個以上で注意表示を出す。

### 5.2 習慣目標

| 項目 | 内容 |
|---|---|
| タイトル | 例「朝の畑見回り」「読書30分」 |
| 頻度 | 毎日／週N回（1〜7）／特定曜日 |
| 進捗 | 達成日数 ÷ 期待日数（今日までの累計）。「今週」の達成率も併記 |
| 連続記録 | 現在の連続達成日数と最長記録 |

- 毎日のチェックはデイリーページで行う。ダッシュボードにはヒートマップ（92マスのカレンダー）で表示する。

### 5.3 ターム全体の進捗

- 経過率: 経過日数 ÷ 全日数
- プロジェクト目標の平均進捗、習慣目標の平均達成率
- 「経過率に対して進捗が20ポイント以上遅れている目標」を赤で強調する

### 5.4 タスクの積み上げと達成／未達成（タスク台帳）

デイリーページで書いた「今日やるべきこと3つ」は、ターム内で最大 276件（92日×3）積み上がる。
これを1つの表として見て、できた／できなかったをチェックし、ターム終了後に総括する。

**タスクの状態**

| 状態 | 意味 | 付け方 |
|---|---|---|
| 未着手 | まだ何もしていない | 作成時の既定 |
| できた | 完了した | チェックボックスON（デイリーページ・台帳・Notion のどこからでも） |
| できなかった | その日にやれなかった | その日の 24:00 を過ぎても未完了なら自動で「できなかった」にする。手動でも付けられる |
| 翌日へ送った | できなかったタスクを別の日に移した | 台帳の「翌日へ送る」操作。元タスクは「送った」扱いで、送り先に新タスクを作る（送った回数を記録） |

**タスク台帳画面**（`/term/:id/tasks`）

- 表の列: 日付（Day N）／タスク／状態／紐づく目標／メモ／Notionリンク
- フィルタ: 全部／できた／できなかった／未着手／目標ごと／週ごと
- 上部に集計: 総数、できた数と率、できなかった数と率、目標別の達成率
- できなかったタスクには「翌日へ送る」「今日に送る」「取り下げ」の操作を付ける
- 行をタップするとその日のデイリーページへ移動

**ターム終了後の総括**（ターム終了日を過ぎると台帳の上部に表示、`/term/:id/review`）

- 「できたこと」一覧（日付順、目標別にグループ化）
- 「できなかったこと」一覧（送った回数が多いものを上に。繰り返し先送りしたものが目に入るように）
- 数字: 達成率、目標別達成率、曜日別達成率（どの曜日に崩れやすいかを見る）、記入率
- 「次のタームに持ち越す」チェック → 次タームの目標設定画面にそのまま流し込める
- 過去のタームの総括はいつでも見返せる

デイリーページ側には、その日のタスク欄の下に「今タームの達成率 ○○%（できた 45 / できなかった 12 / 未着手 3）」を小さく表示し、台帳へのリンクを置く。

## 6. デイリーページ

URL: `/day/2026-10-01` のように日付で1ページ。今日のページがトップに開く。前日／翌日へは左右ボタンとスワイプで移動。

### 6.1 レイアウト（上から順）

1. **ヘッダー**: 日付・曜日、Day N / 92、ターム名、残り日数
2. **今タームの目標（常時表示）**
   - プロジェクト目標: タイトル＋進捗バー。タップでマイルストーンを開いてその場でチェックできる
   - 習慣目標: タイトル＋今日のチェックボックス（ここでチェック＝今日達成）
   - PCでは右カラムに固定表示、スマホでは折りたたみ可能な上部カードにする（既定は開いた状態）
3. **今日のスケジュール（Googleカレンダー）**
   - 当日の予定を時刻順に一覧。終日予定は先頭
   - 「＋予定を追加」: タイトル・開始／終了（または終日）・メモ を入力し、Googleカレンダーに直接作成
   - 各予定のタップで編集・削除（Googleカレンダー側に即反映）
   - 対象カレンダーは設定画面で選ぶ（複数可、既定はメインカレンダー）
   - 明日の予定も折りたたみで見られる
4. **今日やるべきこと 3つ**
   - 3行固定のタスク欄。チェックで完了。4つ目は追加できない（紙版の「3つに絞る」を守る）
   - 各タスクはプロジェクト目標に紐づけ可能（任意）。紐づけると目標側の「関連タスク」に出る
   - 日付が変わっても未完了のタスクは自動で「できなかった」になる（台帳に積み上がる）。過去日のページでは「できなかった」に取り消し線を付け、その場で「できた」に直すことも可能
   - 保存と同時に Notion へ同期される（7.5節）
5. **今日、集中すべきこと**: 1行テキスト（1つだけ）
6. **良かったこと**: 3行（1行ずつの入力欄。3つ埋まると小さな祝福アニメ）
7. **メモ**（自由記述、Markdown可）
8. フッター: 「今日の記入を完了」ボタン（記入済みフラグ。ダッシュボードの記入率に使う）

### 6.2 保存

- すべての欄は入力後 1秒で自動保存（デバウンス）。保存状態を右上に小さく表示
- オフライン時はローカルに保持し、復帰時に送る（フェーズ1では「保存できません」表示のみ、再送はフェーズ2）

## 7. Googleカレンダー連携

| 項目 | 内容 |
|---|---|
| 認証 | Google OAuth 2.0（認可コードフロー）。ログインと同時にカレンダー権限を求める |
| スコープ | `openid` `email` `profile` `https://www.googleapis.com/auth/calendar.events` `https://www.googleapis.com/auth/calendar.readonly`（カレンダー一覧取得用） |
| トークン | リフレッシュトークンをサーバー側（D1）に暗号化して保存。アクセストークンは都度更新 |
| 読み取り | `events.list`（timeMin/timeMax = 当日0:00〜翌0:00、JST、singleEvents=true、orderBy=startTime） |
| 書き込み | `events.insert` / `events.patch` / `events.delete` |
| タイムゾーン | Asia/Tokyo 固定 |
| キャッシュ | 当日分は5分キャッシュ。追加・編集・削除後は即再取得 |
| エラー | 権限切れ時は「Googleに再接続」ボタンを出す |

Googleカレンダーの予定はアプリのDBには保存しない（常にGoogleが正）。

### 7.5 Notion 連携（やるべきことの同期）

やるべきことを Notion のデータベースに同期し、Notion 側からも一覧・チェックできるようにする。
**アプリが正（マスター）**で、Notion は写し＋完了チェックの入口とする。

| 項目 | 内容 |
|---|---|
| 認証 | Notion 内部インテグレーション（Internal Integration Token）。ユーザーが Notion で作成し、対象データベースにコネクトを追加。トークンは Wrangler secret `NOTION_TOKEN`、DB は `NOTION_TASKS_DB_ID` |
| 対象データベース | 「フィニッシャージャーナル タスク」（新規作成、または既存DBを指定。確認事項 9） |
| 同期方向 | アプリ → Notion: 作成・タイトル変更・状態変更・日付移動・削除（アーカイブ）を即時反映。Notion → アプリ: **完了チェックと状態のみ**取り込む（タイトル等の編集はアプリ側が正） |
| 取り込みのタイミング | デイリーページ／台帳を開いたとき、および 15分ごとの Cron Trigger で、Notion の `last_edited_time` が前回同期より新しいページを取得して反映 |
| 衝突 | 両側が同時に変わった場合は Notion の状態を優先（本人がNotionで意図的に操作した、とみなす） |
| 失敗時 | Notion API エラー時はアプリ側の保存は成功させ、未同期フラグを付けて次回リトライ。台帳に「Notion未同期」バッジ |
| レート制限 | Notion は 3リクエスト/秒。キューで直列化し、1日の3タスク一括保存はまとめて送る |

**Notion データベースのプロパティ**

| プロパティ | 型 | 内容 |
|---|---|---|
| タスク | タイトル | タスク名 |
| 日付 | 日付 | 予定日 |
| 状態 | セレクト | 未着手／できた／できなかった／翌日へ送った／取り下げ |
| 完了 | チェックボックス | 「できた」と連動（Notion で手早くチェックするため） |
| 目標 | セレクト | 紐づくプロジェクト目標名（目標名の変更時はアプリ側から更新） |
| ターム | セレクト | 例「2026Q4（10/1〜12/31）」 |
| Day | 数値 | Day N |
| 送った回数 | 数値 | 先送り回数 |
| アプリURL | URL | デイリーページへのリンク |
| アプリID | テキスト | `daily_tasks.id`（照合用、編集不可の想定） |

- Notion 側で新規行を作った場合、日付があればアプリのその日のタスクとして取り込む（3件を超える場合は4件目以降を「Notionから追加」として別枠表示。3つ固定の原則は崩さない）。日付がなければ取り込まない。
- 習慣目標・良かったこと・メモは Notion に送らない（フェーズ2で「良かったこと」の同期を検討）。

## 9. 技術構成（推奨案）

| 層 | 選定 | 理由 |
|---|---|---|
| ホスティング | Cloudflare Workers（静的アセット同梱）| 既存サービスと同じ基盤。OAuthのコールバックとAPIを同じドメインで持てる |
| バックエンド | Hono（TypeScript） | Workers向けの軽量フレームワーク |
| DB | Cloudflare D1（SQLite） | 個人利用の規模で十分。バックアップは `wrangler d1 export` を週次 |
| フロント | React + Vite + TypeScript | SPA。日付移動やチェックの即時反映がしやすい |
| 認証 | Google OAuth 2.0 + 署名付きCookieセッション | 許可メール（環境変数 `ALLOWED_EMAILS`）以外は拒否 |
| ドメイン | `journal.yusando.com`（仮） | Route 53 で CNAME → Workers カスタムドメイン |
| 秘密情報 | Wrangler secrets | `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `SESSION_SECRET` `TOKEN_ENC_KEY` `NOTION_TOKEN` `NOTION_TASKS_DB_ID` |
| 定期処理 | Workers Cron Triggers | 毎日 0:05 JST に未完了タスクを「できなかった」へ更新、15分ごとに Notion 差分取り込み |

代替案: フロントを GitHub Pages（`docs/`）に置き、Worker はAPIのみにする構成も可能。ただしOAuthコールバックとCookieのドメインが分かれて手間が増えるため、Workers一本を推す。

### 9.2 API（すべて `/api/` 配下、セッション必須）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/auth/google` → `/auth/callback` | OAuth。成功時 `/` へ |
| POST | `/api/logout` | セッション破棄 |
| GET/POST | `/api/terms` | 一覧／作成 |
| GET/PATCH | `/api/terms/:id` | 詳細（目標・進捗を含む）／更新 |
| GET/POST | `/api/terms/:id/goals` | 目標一覧／作成 |
| PATCH/DELETE | `/api/goals/:id` | 更新／削除 |
| POST/PATCH/DELETE | `/api/goals/:id/milestones[/:mid]` | マイルストーン |
| PUT | `/api/goals/:id/habit/:date` | その日の習慣チェック（done: true/false） |
| GET/PUT | `/api/days/:date` | デイリーページの取得／保存（タスク・良かったこと含む） |
| GET | `/api/days?from=&to=` | 月カレンダー用の要約（記入済み・習慣達成数） |
| GET | `/api/terms/:id/tasks?status=&goal_id=` | タスク台帳（集計を含む） |
| POST | `/api/tasks/:id/carry` | 翌日（または指定日）へ送る |
| PATCH | `/api/tasks/:id` | 状態変更（できた／できなかった／取り下げ） |
| GET | `/api/terms/:id/review` | ターム総括（できた／できなかった一覧、達成率） |
| POST | `/api/notion/sync` | Notion 差分の手動取り込み |
| GET | `/api/notion/status` | 接続状態・最終同期・未同期件数 |
| GET | `/api/calendar/calendars` | 連携可能なカレンダー一覧 |
| GET | `/api/calendar/events?date=` | 当日の予定 |
| POST/PATCH/DELETE | `/api/calendar/events[/:eventId]` | 予定の作成／更新／削除（Googleに転送） |

進捗の計算はサーバー側で行い、`GET /api/terms/:id` と `GET /api/days/:date` の応答に含める。

## 10. Google標準装備（web-google-standard）

本アプリは本人専用のため、計測・SEOは**公開ページ（ログイン画面）に限定**する。

- `google-ids.json` をリポジトリ直下に置く（GA4は共通 `G-9JG1FFTL1B`、`site` パラメータは `finisher-journal`）
- ログイン画面のみ gtag・title/description/canonical/OGP・JSON-LD（`WebApplication`）を入れる
- ログイン後の画面は `noindex,nofollow`、gtag なし（管理ページ扱い）
- `robots.txt` は `/login` 以外を Disallow。`sitemap.xml` は `/login` のみ。`404.html` を用意
- 本番ドメイン以外では送信しないガードを入れる
- 成果イベント: `sign_up`（初回ログイン）、`app_action_complete`（「今日の記入を完了」）の2つ

## 11. 確認事項（回答をもとに v0.2 へ）

1. **「週刊」の意味**: 音声の文字起こしでは「プロジェクトと週刊」とありました。紙版の構成から **「習慣（しゅうかん）目標」** と解釈して本仕様を書いています。もし「週間目標（1週間ごとの目標）」の意味でしたら、5.2 を「週ごとの目標＋週次レビュー」に組み替えます。
2. **利用者**: ご本人1名の想定で良いか（スタッフも使うなら、ユーザーごとにタームを分ける設計は同じで、許可メールを増やすだけ）。
3. **連携するカレンダー**: メインカレンダーだけか、悠三堂の共有カレンダーなども対象にするか。
4. **ドメイン**: `journal.yusando.com` で良いか。
5. **やるべきこと3つの繰り越し**: 未完了を翌日に自動で持ち越すか（フェーズ2案）、毎日まっさらにするか。
6. **良かったこと**: 3行固定で良いか、自由行数か。
7. **週次レビュー**: 紙版で使っている週末のふりかえり欄があれば、その項目を教えてください（フェーズ2で入れます）。
8. **紙の現物**: 実際のページの写真を1〜2枚いただけると、欄の並びと名称を紙版に揃えます。
9. **Notion のデータベース**: 新しく「フィニッシャージャーナル タスク」を作るか、既にお使いのタスクDBに同期するか。既存DBの場合はそのページのリンクをください（プロパティ名を合わせます）。
10. **Notion 側で編集する範囲**: 完了チェックだけで良いか、タスク名の変更や新規追加も Notion からしたいか（本仕様は「完了チェック＋新規追加は日付付きのみ」）。
11. **「できなかった」の自動判定**: 日付が変わった時点で未完了を自動で「できなかった」にする方針で良いか（翌朝チェックする使い方なら、判定を「翌日の正午」にずらせます）。
