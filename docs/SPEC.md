# 目標達成ジャーナル｜90日の挑戦 仕様書

アプリ名: **目標達成ジャーナル**（副題: 90日の挑戦）。紙の「フィニッシャージャーナル」をもとにしている。

- 版: v0.5（紙版に合わせて、数値目標・大きな障害と対策・時間があればやることを追加）
- 作成日: 2026-09-27
- 対象: 紙の「フィニッシャージャーナル」（90日ジャーナル）をWebアプリ化する
- ステータス: **実装済み（フェーズ1）**。2026-09-27 に方向性OK、確認事項は提案どおりで確定。残るのはドメインのみ（11章）

---

## 1. 目的と背景

紙で長らく使ってきた90日ジャーナルを、スマホ・PCのどちらからでも書けるWebアプリにする。
紙の良さ（1日1ページ、3ヶ月目標が常に目に入る）を保ちながら、次の点を改善する。

- 3ヶ月の目標を**毎日のページに必ず表示**し、忘れないようにする
- 目標ごとの**達成度合い（進捗）を自動で可視化**する
- スケジュール欄は **Googleカレンダーそのもの**を読み書きし、二重管理をなくす
- 毎日の「やるべきこと」を **タームを通して積み上げ**、92日後に「何ができて、何ができなかったか」を一覧で見られるようにする
- やるべきことは **Notion と連携**し、Notion 側からも見て・チェックできるようにする
- **週間・月間の予定とレビュー**を持ち、週・月・3ヶ月をタブで行き来できるようにする
- 3ヶ月ごとに新しいタームを作り、過去のタームも振り返れるようにする

## 2. 用語

| 用語 | 意味 |
|---|---|
| ターム | 3ヶ月（約90日）の1単位。目標はターム単位で立てる。最初は 2026-10-01〜2026-12-31 |
| プロジェクト目標 | ターム中に「完了」させる成果物型の目標。マイルストーン（小タスク）の完了率で進捗を出す |
| 習慣目標 | ターム中に「続ける」行動型の目標。毎日のチェックの積み上げで進捗を出す（※下記 確認事項 1） |
| デイリーページ | 1日1ページのジャーナル。スケジュール／やるべきこと3つ／集中すべきこと／習慣チェック／良かったこと |
| Day N | タームの何日目か。10/1 が Day 1、12/31 が Day 92 |
| タスク台帳 | タームの全日のやるべきことを1つの表にした画面。できた／できなかったをチェックし、ターム終了後に総括を表示する |

## 3. スコープ

### 3.1 フェーズ1（MVP：今回作るもの）

1. Googleアカウントでログイン（利用者は本人のみ。許可メールアドレスのみ通す）
2. タームの作成・一覧・切り替え
3. ターム目標の設定（プロジェクト目標／習慣目標）と進捗表示
4. デイリーページ（1日1ページ、自動保存）
5. デイリーページ上での Googleカレンダー連携（当日の予定の表示・追加・編集・削除）
6. タームのダッシュボード（残り日数、各目標の進捗、習慣の達成カレンダー）
7. タスク台帳（ターム内の全タスクの一覧、できた／できなかったのチェック、ターム終了時の総括）
8. Notion連携（やるべきことを Notion データベースへ同期。完了チェックは双方向）
9. 週間予定・週間レビュー、月間予定・月間レビュー（6.3節）
10. 「今日／週間／月間／3ヶ月」のタブ切り替え（8章）

### 3.2 フェーズ2（あとで）

- タームの最終ふりかえりページ（達成した／しなかった／次に活かす）
- 未完了タスクの翌日への自動繰り越し（台帳の「できなかった」から翌日へ送る操作はフェーズ1に含める）
- 「良かったこと」の一覧・検索
- 通知（朝のリマインド：メール or カレンダー通知）
- 紙ジャーナルの過去分の取り込み（手入力用の一括入力画面）

### 3.3 やらないこと

- 複数人での共有・コメント機能
- ネイティブアプリ（PWA としてホーム画面追加で代替）
- Googleカレンダー以外のカレンダー連携
- Notion 以外のタスクツール連携（Todoist 等）

## 4. ターム（90日）の扱い

- タームは **開始日・終了日・タイトル** を持つ。既定は暦の四半期（10/1〜12/31、1/1〜3/31、…）。
- 「90日」は呼称であり、実際の日数は暦どおり（最初のタームは 92日）。Day 表記は実日数で数える。
- 同時に有効なタームは1つ。終了日を過ぎたら「次のタームを作る」ボタンをダッシュボードに出す。
  次タームを作るとき、前タームの未達目標を引き継ぐか選べる。
- 過去タームは読み取り専用で閲覧できる（目標・進捗・各日のページ）。

## 5. 目標と進捗

### 5.1 プロジェクト目標

| 項目 | 内容 |
|---|---|
| タイトル | 例「新茶の卸先を3件増やす」 |
| なぜやるか（任意） | 動機の一言。デイリーページのツールチップに出す |
| 期限 | 既定はターム終了日。前倒しも可 |
| 数値目標（任意） | 開始値・現在値・目標値・単位。入っていれば進捗 =（現在値−開始値）÷（目標値−開始値）。減らす目標にも対応 |
| 大きな障害と対策（任意） | うまくいかなくなるとしたら何が原因か、とその対策。習慣目標にも付けられる |
| マイルストーン | 小タスクのリスト（3〜10個程度）。チェックで完了 |
| 進捗 | 数値目標があればその達成率。なければ完了マイルストーン数 ÷ 全マイルストーン数（%）。どちらもなければ手動の％スライダー |
| 状態 | 進行中／達成／未達／中止 |

- 目標数の目安は 3〜5個。上限は設けないが、6個以上で注意表示を出す。

### 5.2 習慣目標

| 項目 | 内容 |
|---|---|
| タイトル | 例「朝の畑見回り」「読書30分」 |
| 頻度 | 毎日／週N回（1〜7）／特定曜日 |
| 進捗 | 達成日数 ÷ 期待日数（今日までの累計）。「今週」の達成率も併記 |
| 連続記録 | 現在の連続達成日数と最長記録 |

- 毎日のチェックはデイリーページで行う。ダッシュボードにはヒートマップ（92マスのカレンダー）で表示する。

### 5.3 ターム全体の進捗

- 経過率: 経過日数 ÷ 全日数
- プロジェクト目標の平均進捗、習慣目標の平均達成率
- 「経過率に対して進捗が20ポイント以上遅れている目標」を赤で強調する

### 5.4 タスクの積み上げと達成／未達成（タスク台帳）

デイリーページで書いた「今日やるべきこと3つ」は、ターム内で最大 276件（92日×3）積み上がる。
これを1つの表として見て、できた／できなかったをチェックし、ターム終了後に総括する。

**タスクの状態**

| 状態 | 意味 | 付け方 |
|---|---|---|
| 未着手 | まだ何もしていない | 作成時の既定 |
| できた | 完了した | チェックボックスON（デイリーページ・台帳・Notion のどこからでも） |
| できなかった | その日にやれなかった | その日の 24:00 を過ぎても未完了なら自動で「できなかった」にする。手動でも付けられる |
| 翌日へ送った | できなかったタスクを別の日に移した | 台帳の「翌日へ送る」操作。元タスクは「送った」扱いで、送り先に新タスクを作る（送った回数を記録） |

**タスク台帳画面**（`/term/:id/tasks`）

- 表の列: 日付（Day N）／タスク／状態／紐づく目標・送った回数・Notion 同期の印／操作（週ごとにまとめて表示）
- フィルタ: 全部／できた／できなかった／未着手／目標ごと／週ごと
- 上部に集計: 総数、できた数と率、できなかった数と率、目標別の達成率
- できなかったタスクには「翌日へ送る」「今日に送る」「取り下げ」の操作を付ける
- 行をタップするとその日のデイリーページへ移動

**ターム終了後の総括**（ターム終了日を過ぎると台帳の上部に表示、`/term/:id/review`）

- 「できたこと」一覧（日付順、目標別にグループ化）
- 「できなかったこと」一覧（送った回数が多いものを上に。繰り返し先送りしたものが目に入るように）
- 数字: 達成率、目標別達成率、曜日別達成率（どの曜日に崩れやすいかを見る）、記入率
- 「次のタームに持ち越す」チェック → 次タームの目標設定画面にそのまま流し込める
- 過去のタームの総括はいつでも見返せる

デイリーページ側には、その日のタスク欄の下に「今タームの達成率 ○○%（できた 45 / できなかった 12 / 未着手 3）」を小さく表示し、台帳へのリンクを置く。

## 6. デイリーページ

URL: `/day/2026-10-01` のように日付で1ページ。今日のページがトップに開く。前日／翌日へは左右ボタンとスワイプで移動。

### 6.1 レイアウト（上から順）

1. **ヘッダー**: 日付・曜日、Day N / 92、ターム名、残り日数
2. **今タームの目標（常時表示）**
   - プロジェクト目標: タイトル＋進捗バー。タップでマイルストーンを開いてその場でチェックできる
   - 習慣目標: タイトル＋今日のチェックボックス（ここでチェック＝今日達成）
   - PCでは右カラムに固定表示、スマホでは折りたたみ可能な上部カードにする（既定は開いた状態）
3. **今日のスケジュール（Googleカレンダー）**
   - 当日の予定を時刻順に一覧。終日予定は先頭
   - 「＋予定を追加」: タイトル・開始／終了（または終日）・メモ を入力し、Googleカレンダーに直接作成
   - 各予定のタップで編集・削除（Googleカレンダー側に即反映）
   - 対象カレンダーは設定画面で選ぶ（複数可、既定はメインカレンダー）
   - 明日の予定も折りたたみで見られる
4. **今日やるべきこと 3つ**
   - 3行固定のタスク欄。チェックで完了。4つ目は追加できない（紙版の「3つに絞る」を守る）
   - 各タスクはプロジェクト目標に紐づけ可能（任意）。紐づけると目標側の「関連タスク」に出る
   - 日付が変わっても未完了のタスクは自動で「できなかった」になる（台帳に積み上がる）。過去日のページでは「できなかった」に取り消し線を付け、その場で「できた」に直すことも可能
   - 保存と同時に Notion の「Todo リスト」へ同期される（7.5節）
   - 「Notionから選ぶ」ボタンで、Todo リストに溜まっている Inbox／今週の対応事項などから今日の3つに引き込める
5. **時間があればやること**（Might Do）: 最大10個。チェックで完了。できなくても「できなかった」にならず、台帳の集計・Notion 同期の対象外。メニューから「やるべきことに上げる」（空き枠があるとき）、逆に未着手のやるべきことは「時間があれば」に下げられる
6. **今日、集中すべきこと**: 1行テキスト（1つだけ）
7. **良かったこと**: 3行（1行ずつの入力欄。3つ埋まると小さな祝福アニメ）
8. **一言日記**（今日をひとことで。自由記述）
8. フッター: 「今日の記入を完了」ボタン（記入済みフラグ。ダッシュボードの記入率に使う）

### 6.2 保存

- すべての欄は入力が止まって 1秒後に自動保存。保存状態を右上に小さく表示
- 保存が済むまでは端末内に下書きを残す。ページを閉じる瞬間は sendBeacon でも送る。送信が届かなかった場合も、次にそのページを開いたときに下書きから復元して保存し直す
- タスクや習慣のチェックは押した瞬間に画面へ反映し、保存は裏で行う（失敗したら元に戻す）

### 6.3 週間・月間（予定とレビュー）

週は月曜始まり。週・月それぞれに「予定」と「レビュー」の2つのタブを持つ。

**週間予定**（`/week/月曜の日付`）
- 前回の週間レビューで書いた「来週に活かすこと」を上部に表示
- 週のテーマ（1行）、週の目標（チェック付き、最大10個）、メモ
- 3ヶ月の目標の進捗（プロジェクト）
- 7日分の列: Googleカレンダーの予定、その日のタスクと状態、集中すべきこと、記入完了の印。各日に「＋」で予定を追加
- 今週の習慣の表（曜日×習慣。マスを押すと達成を記録）

**週間レビュー**（`/week/月曜の日付/review`）
- 数字: タスク達成率（前週比）、できた／できなかった、習慣の達成率、記入した日数
- 週の目標の結果（チェック）
- 目標別の達成率、習慣の表
- できたこと／できなかったこと（できなかったものはその場で「今日に送る」「明日に送る」）
- その週の「良かったこと」の一覧
- ふりかえり: 良かったこと・できたこと／うまくいかなかったこと／学び・気づき／来週に活かすこと／自己評価（星5つ）／「レビュー完了」

**月間予定**（`/month/1日の日付`）
- 前回の月間レビューの「来月に活かすこと」、月のテーマ、月の目標、メモ
- 月カレンダー: 予定（1日3件まで）、タスクの点（できた=緑・できなかった=赤・未着手=灰）、記入完了の日は背景色。日付を押すとその日のページ
- この月に含まれる週の一覧（テーマ・達成率・レビュー済みか）

**月間レビュー**（`/month/1日の日付/review`）
- 数字（前月比）、月の目標の結果、週ごとのふりかえり一覧（テーマ・達成率・自己評価・レビュー済みか）
- 目標別、習慣（達成回数／予定回数）、3ヶ月の目標の進み具合
- できたこと／できなかったこと、良かったことの一覧
- ふりかえり（「来月に活かすこと」は翌月の月間予定に表示）

## 7. Googleカレンダー連携

| 項目 | 内容 |
|---|---|
| 認証 | Google OAuth 2.0（認可コードフロー）。ログインと同時にカレンダー権限を求める |
| スコープ | `openid` `email` `profile` `https://www.googleapis.com/auth/calendar.events` `https://www.googleapis.com/auth/calendar.readonly`（カレンダー一覧取得用） |
| トークン | リフレッシュトークンをサーバー側（D1）に暗号化して保存。アクセストークンは都度更新 |
| 読み取り | `events.list`（timeMin/timeMax = 当日0:00〜翌0:00、JST、singleEvents=true、orderBy=startTime） |
| 書き込み | `events.insert` / `events.patch` / `events.delete` |
| タイムゾーン | Asia/Tokyo 固定 |
| キャッシュ | 当日分は5分キャッシュ。追加・編集・削除後は即再取得 |
| エラー | 権限切れ時は「Googleに再接続」ボタンを出す |

Googleカレンダーの予定はアプリのDBには保存しない（常にGoogleが正）。

### 7.5 Notion 連携（やるべきことの同期）

やるべきことは、既にお使いの Notion データベース **「🎒 Todo リスト」（MY LIFE OS 内）** に同期する。新しいDBは作らない。

**送る対象（2026-09-28 変更）**: アプリで作ったタスクは **「できた」にしたものだけ** を、完了の記録として Todo リストに追加する。未着手・できなかった・送ったタスクは Notion に出さない。「できた」を外すと、その行は Notion から片付ける（アーカイブ）。Notion から選んだ行・Notion で作って取り込んだ行は、もともと Notion の行なので、これまでどおり状態（できなかった・日付の移動など）を同期する。
**アプリが正（マスター）**で、Notion は写し＋完了チェック＋タスクの供給元とする。

| 項目 | 内容 |
|---|---|
| 連携先 | データベース `6ecc0a27e7af4782be9c2b022a75b0e8`（データソース `4bbd6ef0-428f-4999-bbff-64cae31fac27`）。Wrangler secret `NOTION_TASKS_DB_ID` に設定 |
| 認証 | Notion 内部インテグレーションのトークン（`NOTION_TOKEN`）。ユーザーが Notion の「設定 → コネクト」で作成し、「MY LIFE OS」ページにコネクトを追加する（子の Todo リストにも権限が及ぶ） |
| 触る範囲 | **タグに「目標達成ジャーナル」が付いた行だけ**。それ以外の行（ルーティン、来客、家族の用事など）は読み書きしない |
| 同期方向 | アプリ → Notion: 「できた」にしたアプリのタスクを追加（外したら片付ける）。Notion の行（選んだ・取り込んだもの）は状態変更・日付移動・取り下げを即時反映。Notion → アプリ: 完了チェック・ステータス・日付の変更、および新規行（タグ＋日付あり）を取り込む。タスク名は Notion 側の変更も取り込む（本人が直した、とみなす） |
| 取り込みのタイミング | デイリーページ／台帳を開いたとき、および 15分ごとの Cron Trigger。`last_edited_time` が前回同期より新しい行だけ取得 |
| 衝突 | 最後に同期した値を覚えておき、Notion 側で変わった項目だけを取り込む（自分の書き込みの跳ね返りは無視）。同期は「取り込み → 送信」の順で行い、Notion での編集を古い値で上書きしない |
| 失敗時 | Notion API エラー時もアプリ側の保存は成功させ、未同期フラグを付けて次回リトライ。台帳に「Notion未同期」バッジ |
| レート制限 | 3リクエスト/秒。キューで直列化し、1日の3タスク一括保存はまとめて送る |

**既存プロパティへの対応（新しいプロパティは追加しない）**

| Todo リストのプロパティ | 型 | アプリからの書き込み |
|---|---|---|
| Name | タイトル | タスク名 |
| Date | 日付 | 予定日（日付のみ、時刻なし） |
| ステータス | セレクト | 未着手→「未着手」／できた→「完了」／できなかった→「**できなかった**」（新規選択肢。初回の書き込みで自動追加）／取り下げ→「キャンセル」。別の日へ送ったときは行を複製せず、**同じ行の Date を送り先に移す**（内容の「送った回数」が増える） |
| Checked | チェックボックス | 「できた」のとき ON。Notion で手早くチェックする用 |
| タグ | マルチセレクト | 「**目標達成ジャーナル**」を必ず付ける（新規選択肢）。紐づく目標があれば目標名のタグも追加（例「カフェ作り」）。既存のタグは消さない |
| 内容 | テキスト | `Day 12 ｜ 目標: ○○ ｜ 送った回数: 1` の形で自動記入 |
| URL | URL | デイリーページへのリンク（末尾に `#task-<アプリID>` を含め、照合キーにも使う） |
| 担当者 | マルチセレクト | 「礒﨑遼太郎」 |
| 優先度／場所／所要時間／プライベート ほか | — | アプリからは触らない（Notion 側で自由に使える） |

追加される選択肢は **ステータス「できなかった」とタグ「目標達成ジャーナル」の2つ**のみ（2026-09-27 承認済み）。Notion API で値を書いたときに自動で作られる。

**Notion → アプリ の解釈**

| Notion での操作 | アプリ側 |
|---|---|
| Checked を ON、またはステータス「完了」 | できた |
| ステータス「できなかった」 | できなかった |
| ステータス「延期」 | できなかった（台帳で「送る」候補として表示。日付の自動移動はしない） |
| ステータス「キャンセル」 | 取り下げ |
| Date を変更 | その日のタスクへ移動。移動先が3件埋まっていれば4件目以降を「Notionから」の別枠に表示（3つ固定の原則は崩さない） |
| タグ「目標達成ジャーナル」＋Date を付けた新規行 | その日のタスクとして取り込む。日付がなければ取り込まない |
| タグを外す | 同期対象から外れる（アプリ側のタスクは残し、Notionリンクだけ切る） |

**Notion からタスクを選ぶ（供給元としての利用）**

Todo リストには「Inbox／今月対応予定／今週の対応事項／未着手」の行が溜まっているので、デイリーページの「やるべきこと3つ」に **「Notionから選ぶ」** ボタンを置く。

- ステータスが Inbox／今月対応予定／今週の対応事項／未着手 で、まだジャーナルに紐づいていない行を一覧（優先度「高 🔥」を上に、タグ・場所で絞り込み）
- 選ぶと、その行に タグ「目標達成ジャーナル」と Date（今日）と URL を付け、今日の3つに入る。Notion 側でもその日の予定として見える
- 選ぶだけで **Notion 側の行は複製しない**（1タスク＝1行を守る）

習慣目標・良かったこと・一言日記は Notion に送らない（フェーズ2で「良かったこと」の同期を検討）。

### 語学アプリとの連動（90日フランス語・中国語）

- 目標ごとに `link_source`（`lang:fr`／`lang:zh`）を選べる。習慣目標は語学アプリで学習した（XP が付いた）日に ✓ を足す（消さない）。プロジェクト目標はクリアした Day 数 ÷ 90 を `manual_progress` に入れる。
- 語学アプリの記録は Firebase（プロジェクト french90days）の Firestore `progress/{uid}`・`progress-zh/{uid}`。ジャーナルのメールアドレスで Firebase のユーザーを探して読む（サービスアカウントの鍵 `FIREBASE_SERVICE_ACCOUNT`）。
- 15分ごとの定期処理・連動を選んだとき・設定画面の「今すぐ反映」で動く。対象は進行中のタームと、終わって7日以内のターム。
- 計算は `src/shared/langs.ts`、読み込みは `src/worker/firebase.ts`、書き込みは `src/worker/langlink.ts`。

## 9. 技術構成（推奨案）

| 層 | 選定 | 理由 |
|---|---|---|
| ホスティング | Cloudflare Workers（静的アセット同梱）| 既存サービスと同じ基盤。OAuthのコールバックとAPIを同じドメインで持てる |
| バックエンド | Hono（TypeScript） | Workers向けの軽量フレームワーク |
| DB | Cloudflare D1（SQLite） | 個人利用の規模で十分。バックアップは `wrangler d1 export` を週次 |
| フロント | React + Vite + TypeScript | SPA。日付移動やチェックの即時反映がしやすい |
| 認証 | Google OAuth 2.0 + 署名付きCookieセッション | 許可メール（環境変数 `ALLOWED_EMAILS`）以外は拒否 |
| ドメイン | `journal.yusando.com`（仮） | Route 53 で CNAME → Workers カスタムドメイン |
| 秘密情報 | Wrangler secrets | `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `TOKEN_ENC_KEY` `NOTION_TOKEN`（DB ID・タグ名・担当者名は `wrangler.toml` の vars） |
| 定期処理 | Workers Cron Triggers | 15分ごとに、期限を過ぎた未着手タスクを「できなかった」へ更新し、Notion と同期（画面を開いたときにも同じ更新を行う） |
| セッション | D1 の sessions（ランダムID、HttpOnly Cookie、60日） | 書き込み系 API は独自ヘッダ `x-fj` または同一オリジンの Origin を必須にして CSRF を防ぐ |

代替案: フロントを GitHub Pages（`docs/`）に置き、Worker はAPIのみにする構成も可能。ただしOAuthコールバックとCookieのドメインが分かれて手間が増えるため、Workers一本を推す。

## 10. Google標準装備（web-google-standard）

本アプリは本人専用のため、計測・SEOは**公開ページ（ログイン画面）に限定**する。

- `google-ids.json` をリポジトリ直下に置く（GA4は共通 `G-9JG1FFTL1B`、`site` パラメータは `finisher-journal`）
- ログイン画面のみ gtag・title/description/canonical/OGP・JSON-LD（`WebApplication`）を入れる
- ログイン後の画面は `noindex,nofollow`、gtag なし（管理ページ扱い）
- `robots.txt` は `/login` 以外を Disallow。`sitemap.xml` は `/login` のみ。存在しないパスはアプリ内の「ページが見つかりません」を出す（SPA のため 404.html は使わない）
- 本番ドメイン以外では送信しないガードを入れる
- 成果イベント: `login`（「Googleでログイン」を押したとき、`site: finisher-journal` 付き）。ログイン後の画面には計測タグを入れない方針のため、`app_action_complete` は送らない

## 15. グレート・ロックイン（v0.7）

タームごとに切り替える集中モード。3ヶ月 → 「ロックイン」タブで「このタームをロックインにする」を押すと有効になる。

| 機能 | 中身 |
|---|---|
| 毎日のルール | 共通3つ（運動30分・瞑想15分〈分けてOK〉・禁酒）は外せない。分の目安だけ変えられる。自分のルールは1〜3つ、全部で6つまで（サーバー側で上限を止める）。「分」のルールは足し算で記録し、目安に届いたら守れた扱い |
| 10倍目標から逆算 | 1年後の10倍目標 → 90日の目標（プロジェクト目標）→ 今週の目標（週間予定）→ 今日のタスク → 進み具合（毎日の「今日の進み具合」）を1画面に階段で表示 |
| イベントモード | 今日のページで切り替え。「飲まない・午前中は作業・翌朝は定刻」の3つをチェック。3つ目は翌日のページでも答えられる。「飲まない」は禁酒ルールの記録にも入る |
| Day 0 基地づくり | 誘惑の断捨離・視覚の最適化・瞑想／作業エリアの6項目 |
| 90日目のイベント | 名前・日付・申し込みの証拠。今日のページに残り日数を表示 |
